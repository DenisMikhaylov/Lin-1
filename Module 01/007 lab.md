# Лабораторная работа: Псевдофайловая система /proc, мониторинг процессов и сигналы в Debian 12

**Тема:** Обзор псевдофайловой системы `/proc`. Просмотр информации о процессах (`ps`, `top`). Управление процессами с помощью сигналов (утилита `kill`).

**Цель работы:**
- Изучить структуру и назначение псевдофайловой системы `/proc`.
- Освоить утилиты мониторинга процессов `ps` и `top`.
- Научиться управлять процессами с помощью сигналов (`kill`, `killall`, `pkill`).

**Оборудование и ПО:**
- Виртуальная машина с Debian 12 (Bookworm).
- Пользователь `root` (пароль `111`), пользователь `user` (пароль `111`).

**Продолжительность:** 2 академических часа (120 минут).

**Предварительные требования:** базовые навыки работы в командной строке Linux.

---

## Теоретическая справка (5 мин)

**`/proc`** — виртуальная (псевдо) файловая система, предоставляемая ядром Linux. Она не хранится на диске, а генерируется «на лету». Через `/proc` можно получить информацию о процессах, ядре, оборудовании и параметрах системы.

**Процесс** — экземпляр выполняющейся программы. Каждый процесс имеет уникальный идентификатор **PID** (Process ID).

**Сигнал** — программное прерывание, отправляемое процессу. Наиболее частые сигналы:
| Сигнал | Номер | Назначение |
|---|---|---|
| `SIGHUP` | 1 | Перечитать конфигурацию / разрыв терминала |
| `SIGINT` | 2 | Прерывание (Ctrl+C) |
| `SIGKILL` | 9 | Принудительное завершение (нельзя перехватить) |
| `SIGTERM` | 15 | Мягкое завершение (по умолчанию у `kill`) |
| `SIGSTOP` | 19 | Приостановить процесс |
| `SIGCONT` | 18 | Продолжить процесс |

## Этап 1. Подготовка (10 мин)

1. Войдите в систему как `root`:
   ```bash
   su -
   # пароль: 111
   ```

2. Проверьте наличие пользователя `user` и при необходимости создайте его:
   ```bash
   id user || (useradd -m -s /bin/bash user && echo 'user:111' | chpasswd)
   ```

3. Установите необходимые утилиты:
   ```bash
   apt update
   apt install -y procps psmisc htop tree
   ```
   - `procps` — содержит `ps`, `top`, `kill`, `free`, `uptime`.
   - `psmisc` — содержит `killall`, `pstree`.
   - `htop` — расширенный монитор процессов (опционально).
   - `tree` — для наглядного отображения структуры каталогов.

4. Проверьте, что `/proc` смонтирован:
   ```bash
   mount | grep proc
   ```
   Ожидаемый результат:
   ```
   proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)
   ```

## Этап 2. Знакомство с псевдофайловой системой /proc (30 мин)

### 2.1. Общий обзор структуры

1. Посмотрите содержимое `/proc`:
   ```bash
   ls /proc
   ```

2. Обратите внимание на:
   - **Числовые каталоги** — по одному на каждый запущенный процесс (имя = PID).
   - **Файлы с общесистемной информацией**: `cpuinfo`, `meminfo`, `version`, `uptime`, `loadavg`, `filesystems`, `mounts`, `cmdline`, `modules`.

3. Просмотрите структуру `/proc` в виде дерева (ограничим глубину):
   ```bash
   tree -L 1 /proc | head -50
   ```

### 2.2. Информация о процессоре

1. Посмотрите сведения о CPU:
   ```bash
   cat /proc/cpuinfo
   ```

2. Выведите только модель процессора:
   ```bash
   grep -m1 "model name" /proc/cpuinfo
   ```

3. Посчитайте количество ядер:
   ```bash
   grep -c ^processor /proc/cpuinfo
   nproc
   ```

### 2.3. Информация о памяти

1. Посмотрите сведения о памяти:
   ```bash
   cat /proc/meminfo
   ```

2. Сравните с выводом утилиты `free -h`:
   ```bash
   free -h
   ```
   **Пояснение:** `free` берёт данные именно из `/proc/meminfo`.

### 2.4. Информация о ядре и системе

1. Версия ядра:
   ```bash
   cat /proc/version
   uname -r
   ```

2. Время работы системы (в секундах):
   ```bash
   cat /proc/uptime
   ```

3. Средняя загрузка системы за 1, 5 и 15 минут:
   ```bash
   cat /proc/loadavg
   uptime
   ```

4. Список файловых систем, поддерживаемых ядром:
   ```bash
   head -20 /proc/filesystems
   ```

5. Смонтированные файловые системы:
   ```bash
   cat /proc/mounts
   ```
   Сравните с `/etc/mtab` и командой `mount`.

6. Параметры командной строки ядра:
   ```bash
   cat /proc/cmdline
   ```

### 2.5. Параметры ядра во время работы

Некоторые файлы в `/proc/sys` позволяют менять параметры ядра «на лету».

1. Посмотрите текущее значение максимального количества открытых файлов:
   ```bash
   cat /proc/sys/fs/file-max
   ```

2. Посмотрите значение `hostname`:
   ```bash
   cat /proc/sys/kernel/hostname
   ```

3. Измените его временно (до перезагрузки):
   ```bash
   echo "debian-lab" > /proc/sys/kernel/hostname
   hostname
   ```
   Верните обратно:
   ```bash
   echo "debian" > /proc/sys/kernel/hostname
   ```

4. Включите перенаправление IP-пакетов (например, для будущей настройки маршрутизатора):
   ```bash
   echo 1 > /proc/sys/net/ipv4/ip_forward
   cat /proc/sys/net/ipv4/ip_forward
   ```
   Отключите обратно:
   ```bash
   echo 0 > /proc/sys/net/ipv4/ip_forward
   ```

> **Совет:** Правильный способ менять параметры ядра — через `sysctl`. Например:
> ```bash
> sysctl net.ipv4.ip_forward
> sysctl -w net.ipv4.ip_forward=1
> ```

### 2.6. Информация о конкретном процессе в /proc

1. Узнайте PID текущей оболочки:
   ```bash
   echo $$
   ```
   Пусть, например, `1234`.

2. Изучите каталог `/proc/<PID>`:
   ```bash
   ls /proc/<PID>
   ```

3. Ключевые файлы:
   - `cmdline` — команда запуска процесса.
   - `cwd` — симлинк на текущий рабочий каталог.
   - `exe` — симлинк на исполняемый файл.
   - `environ` — переменные окружения.
   - `fd/` — открытые файловые дескрипторы.
   - `status` — состояние процесса (имя, PID, PPID, память, пользователь).
   - `limits` — ограничения ресурсов.

4. Выведите содержимое:
   ```bash
   cat /proc/<PID>/cmdline | tr '\0' ' '; echo
   ls -l /proc/<PID>/cwd
   ls -l /proc/<PID>/exe
   cat /proc/<PID>/status
   ```

5. Посмотрите открытые файлы оболочки:
   ```bash
   ls -l /proc/<PID>/fd
   ```

## Этап 3. Просмотр информации о процессах: `ps` (25 мин)

### 3.1. Базовое использование `ps`

1. Только процессы текущей оболочки:
   ```bash
   ps
   ```

2. Все процессы текущего пользователя:
   ```bash
   ps -u root
   ```

3. Все процессы в системе:
   ```bash
   ps -e
   ```

4. Полный формат (BSD-стиль, «лес»):
   ```bash
   ps aux
   ```

5. Полный формат (UNIX-стиль):
   ```bash
   ps -ef
   ```

6. Дерево процессов:
   ```bash
   ps -ejH
   pstree -p
   ```

### 3.2. Полезные комбинации

1. Процессы с высоким потреблением памяти (сортировка по %MEM):
   ```bash
   ps aux --sort=-%mem | head -10
   ```

2. Процессы с высоким потреблением CPU:
   ```bash
   ps aux --sort=-%cpu | head -10
   ```

3. Найти процесс по имени:
   ```bash
   ps aux | grep ssh
   ```

4. Найти процесс по PID:
   ```bash
   ps -p <PID> -o pid,ppid,user,cmd
   ```

5. Выбрать произвольные столбцы:
   ```bash
   ps -eo pid,ppid,user,%cpu,%mem,stat,start,time,cmd
   ```

6. Все процессы, запущенные пользователем `user`:
   ```bash
   ps -u user -o pid,cmd
   ```

### 3.3. Формирование собственной команды

Задание: выведите таблицу со столбцами **PID, PPID, USER, %CPU, %MEM, STAT, CMD**, отсортированную по убыванию %CPU, первые 15 строк:
```bash
ps -eo pid,ppid,user,%cpu,%mem,stat,cmd --sort=-%cpu | head -15
```

### 3.4. Поиск «зомби» и «спящих» процессов

1. Процессы в состоянии **Z** (zombie):
   ```bash
   ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/ {print}'
   ```

2. Процессы в состоянии **D** (непрерываемый сон):
   ```bash
   ps -eo pid,ppid,stat,cmd | awk '$3 ~ /D/ {print}'
   ```

### 3.5. Утилита `pidof`

```bash
pidof systemd
pidof sshd
```

## Этап 4. Мониторинг в реальном времени: `top` (25 мин)

### 4.1. Запуск `top`

```bash
top
```
**Разбор вывода:**
- **Строка 1**: время работы, число пользователей, load average.
- **Строка 2**: количество задач (процессов) в разных состояниях.
- **Строка 3**: загрузка CPU (us, sy, ni, id, wa, hi, si, st).
- **Строка 4–5**: память (RAM и swap).
- **Таблица процессов**: PID, USER, PR, NI, VIRT, RES, SHR, S, %CPU, %MEM, TIME+, COMMAND.

### 4.2. Интерактивные команды `top`

Нажмите `?` для справки. Основные клавиши:

| Клавиша | Действие |
|---|---|
| `h` / `?` | Справка |
| `q` | Выход |
| `P` | Сортировка по %CPU |
| `M` | Сортировка по %MEM |
| `T` | Сортировка по времени работы |
| `k` | Убить процесс (запросит PID и сигнал) |
| `r` | Изменить `nice` процесса (renice) |
| `1` | Показать загрузку по каждому ядру |
| `c` | Показать полную командную строку |
| `u` | Фильтр по пользователю |
| `f` | Выбор отображаемых полей |
| `W` | Сохранить настройки |

**Упражнение:**
1. Запустите `top`.
2. Нажмите `1` — увидите загрузку каждого CPU.
3. Нажмите `M` — сортировка по памяти.
4. Нажмите `c` — полные команды.
5. Нажмите `q` — выход.

### 4.3. Однократный вывод `top`

Полезно для скриптов и документации:
```bash
top -b -n 1 | head -30
```

### 4.4. Мониторинг конкретного процесса

1. Запустите долгий процесс в фоне (см. также Этап 5):
   ```bash
   sleep 3600 &
   echo $!   # запомните PID
   ```

2. В `top` отфильтруйте по PID: запустите `top`, нажмите `u` (или `-p` из командной строки):
   ```bash
   top -p <PID>
   ```

3. Завершите `sleep`:
   ```bash
   kill <PID>
   ```

### 4.5. Утилита `htop` (опционально)

```bash
htop
```
- F1 — справка, F9 — kill, F10 — выход.
- Более удобное цветное представление, интерактивное управление мышью (если включено в настройках).

### 4.6. Утилита `uptime` и `vmstat`

```bash
uptime
vmstat 1 5
```
- `vmstat 1 5` — 5 отчётов с интервалом 1 секунда (r, b, si, so, bi, bo, us, sy, id, wa).

## Этап 5. Сигналы и утилита `kill` (30 мин)

### 5.1. Получение списка сигналов

1. Все сигналы, известные системе:
   ```bash
   kill -l
   ```

2. Подробное описание:
   ```bash
   man 7 signal
   ```

### 5.2. Запуск тестовых процессов

1. Запустите три «долгоиграющих» процесса `sleep` в фоне и сохраните их PID:
   ```bash
   sleep 1000 &
   PID1=$!
   sleep 1000 &
   PID2=$!
   sleep 1000 &
   PID3=$!
   echo "PID1=$PID1 PID2=$PID2 PID3=$PID3"
   ```

2. Посмотрите их в списке процессов:
   ```bash
   ps -o pid,ppid,stat,cmd -p $PID1,$PID2,$PID3
   ```

### 5.3. Мягкое завершение (SIGTERM = 15)

1. Отправьте сигнал по умолчанию:
   ```bash
   kill $PID1
   ```
   Эквивалентно:
   ```bash
   kill -15 $PID1
   kill -TERM $PID1
   ```

2. Проверьте, что процесс завершился:
   ```bash
   ps -p $PID1
   ```

### 5.4. Принудительное завершение (SIGKILL = 9)

1. Попробуйте завершить `$PID2` мягко:
   ```bash
   kill $PID2
   ps -p $PID2      # если ещё жив — завершаем жёстко
   ```

2. Если процесс «завис» и не реагирует на SIGTERM:
   ```bash
   kill -9 $PID2
   ```
   > **Внимание:** `SIGKILL` нельзя перехватить или проигнорировать — процесс завершается немедленно ядром. Файловые дескрипторы закрываются ядром, но данные в буферах могут быть потеряны.

### 5.5. Приостановка и продолжение (SIGSTOP / SIGCONT)

1. Приостановите `$PID3`:
   ```bash
   kill -STOP $PID3
   ps -o pid,stat,cmd -p $PID3
   ```
   В столбце `STAT` появится `T` (stopped).

2. Продолжите выполнение:
   ```bash
   kill -CONT $PID3
   ps -o pid,stat,cmd -p $PID3
   ```
   Состояние вернётся в `S`.

3. Завершите процесс:
   ```bash
   kill $PID3
   ```

### 5.6. Массовое управление: `killall` и `pkill`

1. Запустите несколько процессов с одинаковым именем:
   ```bash
   sleep 2000 &
   sleep 2000 &
   sleep 2000 &
   pgrep sleep
   ```

2. Завершите их по имени:
   ```bash
   killall sleep
   pgrep sleep    # должно быть пусто
   ```

3. Запустите процессы заново и завершите по шаблону:
   ```bash
   sleep 2000 &
   sleep 2000 &
   pkill -f "sleep 2000"
   ```

4. Отправьте сигнал конкретному пользователю:
   ```bash
   su - user -c "sleep 3000 &"
   pkill -u user -SIGTERM sleep
   ```

### 5.7. Проверка существования процесса: `kill -0`

Сигнал `0` не отправляется процессу, но позволяет проверить, существует ли он:
```bash
sleep 500 &
PID=$!
if kill -0 $PID 2>/dev/null; then
    echo "Процесс $PID существует"
else
    echo "Процесс $PID не существует"
fi
kill $PID
```

### 5.8. Практический сценарий: перезапуск службы через сигнал SIGHUP

1. Многие демоны перечитывают конфигурацию по `SIGHUP`, не завершаясь:
   ```bash
   systemctl status ssh
   PID_SSH=$(pidof sshd | awk '{print $1}')
   echo "PID sshd: $PID_SSH"
   kill -HUP $PID_SSH
   systemctl status ssh    # служба работает, конфиг перечитан
   ```

> **Осторожно:** не отправляйте `SIGHUP` случайным процессам в производственной среде без понимания последствий.

### 5.9. Управление через `top`

1. Запустите `top`.
2. Нажмите `k`.
3. Введите PID процесса (например, любого `sleep`).
4. Введите сигнал (`15` или `9`).
5. Убедитесь, что процесс исчез из списка.

## Приложение. Шпаргалка команд

| Задача | Команда |
|---|---|
| Информация о CPU | `cat /proc/cpuinfo` |
| Информация о памяти | `cat /proc/meminfo` |
| Версия ядра | `cat /proc/version` |
| Load average | `cat /proc/loadavg` |
| Список процессов | `ps aux`, `ps -ef` |
| Дерево процессов | `pstree -p` |
| Сортировка по CPU | `ps aux --sort=-%cpu \| head` |
| Мониторинг в реальном времени | `top`, `htop` |
| Сигналы: список | `kill -l` |
| Отправить сигнал | `kill -TERM <PID>`, `kill -9 <PID>` |
| Завершить по имени | `killall <name>`, `pkill -f <pattern>` |
| Приостановить/продолжить | `kill -STOP <PID>`, `kill -CONT <PID>` |
| Проверить существование | `kill -0 <PID>` |
| Перечитать конфигурацию демона | `kill -HUP <PID>` |

**Ключевые пути в `/proc`:**
```
/proc/cpuinfo        — информация о процессоре
/proc/meminfo        — информация о памяти
/proc/version        — версия ядра
/proc/uptime         — время работы системы
/proc/loadavg        — средняя загрузка
/proc/mounts         — смонтированные ФС
/proc/filesystems    — поддерживаемые ФС
/proc/cmdline        — параметры ядра
/proc/sys/           — изменяемые параметры ядра
/proc/<PID>/         — каталог конкретного процесса
```
