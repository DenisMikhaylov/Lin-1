# Лабораторная работа
## Настройка сетевого интерфейса в Debian 12: `/etc/network/interfaces` и NetworkManager

**Цель работы:** освоить два подхода к настройке сетевого интерфейса в Debian 12 — классический через файл `/etc/network/interfaces` и современный через NetworkManager (`nmcli` и `nmtui`), научиться переключаться между ними и проверять результат.

**Среда выполнения:** Debian 12 (серверная или минимальная установка), пользователь `debian` с правами `sudo`, доступ к консоли или SSH.

**Продолжительность:** 1 академический час.

---

## 1. Теоретические сведения

В Debian 12 сосуществуют два основных механизма управления сетью:

| Механизм | Пакет / служба | Где настраивается | Когда используется |
|---|---|---|---|
| Классический (`ifupdown`) | `ifupdown`, служба `networking` | `/etc/network/interfaces` (и `interfaces.d/`) | Серверы, минимальные установки, простые конфигурации |
| NetworkManager | `network-manager`, служба `NetworkManager` | Профили в `/etc/NetworkManager/system-connections/`, CLI `nmcli`, TUI `nmtui` | Рабочие станции, ноутбуки, динамические сети, Wi-Fi |

**Важное правило совместимости:** по умолчанию NetworkManager **не управляет** интерфейсами, которые объявлены в `/etc/network/interfaces`. Поэтому для чистой работы одного из механизмов нужно либо убрать интерфейс из `/etc/network/interfaces` (если используется NetworkManager), либо не запускать NetworkManager для этого интерфейса (если используется `ifupdown`).

**Проверка текущего состояния:**
```bash
ip -br link                          # список интерфейсов
ip -br addr                          # IP-адреса
systemctl status networking          # служба ifupdown
systemctl status NetworkManager      # служба NetworkManager
nmcli device status 2>/dev/null      # управление устройствами (если NM установлен)
```

## 3. Задание 2. Настройка через `/etc/network/interfaces`

### 3.1. Резервная копия

Перед редактированием системного файла сделайте копию:

```bash
sudo cp /etc/network/interfaces /etc/network/interfaces.bak
```

### 3.2. Просмотр текущей конфигурации

```bash
cat /etc/network/interfaces
```

Обычно файл содержит блок для loopback (`lo`) и, возможно, блок для основного интерфейса.

### 3.3. Настройка DHCP

Откройте файл:

```bash
sudo nano /etc/network/interfaces
```

Для основного интерфейса (замените `<INTERFACE>` на ваш, например `enp0s3`) добавьте или приведите к виду:

```
auto <INTERFACE>
iface <INTERFACE> inet dhcp
```

### 3.4. Настройка статического IP

Для перехода на статический адрес измените блок:

```
auto <INTERFACE>
iface <INTERFACE> inet static
    address 192.168.1.100/24
    gateway 192.168.1.1
    dns-nameservers 8.8.8.8 8.8.4.4
```

Замените `192.168.1.100/24`, `192.168.1.1` и DNS на значения, подходящие для вашей лабораторной сети. Если подсеть неизвестна, уточните у преподавателя или используйте `ip route` до внесения изменений.

### 3.5. Применение конфигурации

```bash
sudo systemctl restart networking
```

Если `restart networking` не применяет изменения корректно, используйте точечный перезапуск интерфейса:

```bash
sudo ifdown <INTERFACE> && sudo ifup <INTERFACE>
```

### 3.6. Проверка

```bash
ip -br addr show <INTERFACE>
ip route
ping -c 3 8.8.8.8
ping -c 3 deb.debian.org
```

Убедитесь, что IP-адрес, шлюз и DNS соответствуют заданным значениям.

### 3.7. Возврат к исходной конфигурации

```bash
sudo mv /etc/network/interfaces.bak /etc/network/interfaces
sudo systemctl restart networking
```

## 4. Задание 3. Настройка через NetworkManager

### 4.1. Установка и запуск NetworkManager

Если пакет не установлен:

```bash
sudo apt update
sudo apt install -y network-manager
```

Запустите и включите автозапуск:

```bash
sudo systemctl enable --now NetworkManager
systemctl status NetworkManager
```

### 4.2. Важное условие: освобождение интерфейса от `ifupdown`

Чтобы NetworkManager мог управлять интерфейсом, он **не должен быть объявлен** в `/etc/network/interfaces`. Сделайте резервную копию и закомментируйте или удалите блок `auto <INTERFACE>` и `iface <INTERFACE> ...` (оставьте только `lo`):

```bash
sudo cp /etc/network/interfaces /etc/network/interfaces.bak_nm
sudo nano /etc/network/interfaces
```

Пример допустимого файла при использовании NetworkManager:

```
auto lo
iface lo inet loopback
```

Затем перезапустите `networking` (чтобы `ifupdown` отпустил интерфейс) и NetworkManager:

```bash
sudo systemctl restart networking
sudo systemctl restart NetworkManager
```

Проверьте, что интерфейс больше не `unmanaged`:

```bash
nmcli device status
```

### 4.3. Настройка статического IP через `nmcli`

Посмотрите список соединений:

```bash
nmcli connection show
```

Если для интерфейса есть готовое соединение (например, `Wired connection 1`), измените его. Если нет — создайте новое.

**Вариант А. Изменение существующего соединения:**
```bash
sudo nmcli connection modify "Wired connection 1" \
    ipv4.method manual \
    ipv4.addresses 192.168.1.100/24 \
    ipv4.gateway 192.168.1.1 \
    ipv4.dns "8.8.8.8 8.8.4.4"
```

**Вариант Б. Создание нового соединения:**
```bash
sudo nmcli connection add type ethernet con-name lab-static ifname <INTERFACE>
sudo nmcli connection modify lab-static \
    ipv4.method manual \
    ipv4.addresses 192.168.1.100/24 \
    ipv4.gateway 192.168.1.1 \
    ipv4.dns "8.8.8.8 8.8.4.4"
```

**Активация соединения:**
```bash
sudo nmcli connection up lab-static
```
Или для существующего:
```bash
sudo nmcli connection down "Wired connection 1"
sudo nmcli connection up "Wired connection 1"
```

### 4.4. Настройка через `nmtui` (текстовый интерфейс)

Запустите:

```bash
sudo nmtui
```

В меню:
1. Выберите **«Edit a connection»**.
2. Выберите нужный интерфейс (или создайте новое через `<Add>`).
3. В поле **IPv4 CONFIGURATION** переключите с `Automatic` на `Manual`.
4. Нажмите `<Show>` и заполните:
   - **Addresses**: `192.168.1.100/24`
   - **Gateway**: `192.168.1.1`
   - **DNS servers**: `8.8.8.8`, `8.8.4.4`
5. Выберите `<OK>`, затем **Quit**.

Примените изменения:
```bash
sudo nmcli connection up "Wired connection 1"
```
Или перезапустите NetworkManager:
```bash
sudo systemctl restart NetworkManager
```

### 4.5. Проверка

```bash
nmcli connection show
nmcli device status
ip -br addr show <INTERFACE>
ip route
ping -c 3 8.8.8.8
ping -c 3 deb.debian.org
```

### 4.6. Возврат к исходному состоянию

```bash
sudo nmcli connection delete lab-static 2>/dev/null
sudo nmcli connection modify "Wired connection 1" ipv4.method auto 2>/dev/null
sudo nmcli connection up "Wired connection 1" 2>/dev/null
sudo mv /etc/network/interfaces.bak_nm /etc/network/interfaces
sudo systemctl restart networking
```

Проверьте и запишите в отчёт ответы на ситуации:

3. После установки NetworkManager перестал работать статический IP, заданный через `/etc/network/interfaces`. Почему это произошло?

**Полезные команды для диагностики:**

## 9. Приложение. Шпаргалка

### `/etc/network/interfaces`

| Задача | Синтаксис |
|---|---|
| DHCP | `auto <iface>`<br>`iface <iface> inet dhcp` |
| Статический IP | `auto <iface>`<br>`iface <iface> inet static`<br>`address 192.168.1.100/24`<br>`gateway 192.168.1.1`<br>`dns-nameservers 8.8.8.8 8.8.4.4` |
| Применить | `sudo systemctl restart networking` |
| Точечно | `sudo ifdown <iface> && sudo ifup <iface>` |

### NetworkManager (`nmcli`)

| Задача | Команда |
|---|---|
| Список соединений | `nmcli connection show` |
| Статус устройств | `nmcli device status` |
| Создать соединение | `nmcli connection add type ethernet con-name <name> ifname <iface>` |
| Задать статический IP | `nmcli connection modify <name> ipv4.method manual ipv4.addresses 192.168.1.100/24 ipv4.gateway 192.168.1.1 ipv4.dns "8.8.8.8 8.8.4.4"` |
| Активировать | `nmcli connection up <name>` |
| Вернуть DHCP | `nmcli connection modify <name> ipv4.method auto` |
| Удалить | `nmcli connection delete <name>` |

### NetworkManager (`nmtui`)

| Действие | Навигация |
|---|---|
| Открыть | `sudo nmtui` |
| Редактировать соединение | `Edit a connection` → выбрать → `Edit` |
| Ручной IPv4 | `IPv4 CONFIGURATION` → `Manual` → `Show` |
| Сохранить | `<OK>` → `Quit` |

### Диагностика

| Задача | Команда |
|---|---|
| IP-адреса | `ip -br addr` |
| Маршруты | `ip route` |
| DNS | `resolvectl status`, `cat /etc/resolv.conf` |
| Логи `networking` | `journalctl -u networking -n 50` |
| Логи NetworkManager | `journalctl -u NetworkManager -n 50` |
